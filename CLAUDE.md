# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

**Basil** (bundle ID `com.erion.basil`) is a native macOS dual-pane file manager in the spirit of Total Commander, written in Swift. **VoiceOver accessibility is a hard requirement** (not a polish item), and the app must also look good. It is for personal use and won't be sold.

Progress, completed milestones and open questions are tracked in **`progress.md`**. Read it at the start of every session. Update it whenever a milestone, decision or open question changes.

## Working rules (from the project owner)

- **Never guess. If something is unclear, ask** (use AskUserQuestion). This applies to library choices, UX behaviour, defaults, naming and anything not settled below or in `progress.md`. Write every new decision in the "Decisions" section of `progress.md`.
- Everything is modular. New features must plug in through the existing registries (providers, operations, archive backends, commands, plugins) instead of being wired directly into the UI.
- **No emojis, symbol glyphs or decorative Unicode anywhere**: UI text, VoiceOver strings, docs, comments. Use plain words ("Cmd+Shift+F6", "Up", "->"). Symbols are read out badly by VoiceOver. No SF Symbol decoration either; real file-type icons are fine.
- **Commit when a feature is done** (no need to ask). Keep `progress.md` updated in the same commit.
- Copy and move integrity is the most important correctness property in the app (see "Secure copy/move").

## Architecture (target design)

Big picture: **UI -> Commands -> Operations Queue -> VFS Providers**. Plugins and integrations hook in through registries at each layer.

```
project.yml             XcodeGen spec (app target "Basil" + BasilUITests); Basil.xcodeproj is generated, gitignored
Config/Base.xcconfig    shared settings: macOS 27, Swift 6 strict concurrency, signing identity "dev"
                        (override locally in Config/Signing.local.xcconfig, gitignored)
App/Sources/            thin app target: main.swift, AppDelegate, main menu, wiring of registries
Tests/BasilUITests/     XCUITests incl. performAccessibilityAudit()
Packages/               one local SwiftPM package per module, each with a <Name>Tests target
  BasilCore/            shared models (VFSPath, FileItem, capabilities), settings store, logging, Keychain wrapper
  BasilVFS/             FileSystemProvider protocol + ProviderRegistry; LocalProvider            (-> Core)
  BasilOperations/      Operation protocol, serial queue (actor), SecureCopyEngine, conflicts   (-> Core, VFS)
  BasilArchives/        ArchiveBackend protocol; libarchive/7-Zip/UnRAR backends; ArchiveProvider (-> Core, VFS, Vendor/libarchive)
  BasilRemote/          one provider per service (SFTP, FTP, Dropbox, WebDAV, S3, GDrive, OneDrive, SMB) (-> Core, VFS)
  BasilGit/             GitService wrapping the git CLI                                          (-> Core)
  BasilSearch/          Spotlight engine + own filename index (scanner, FSEvents, binary store)  (-> Core, VFS)
  BasilSync/            directory compare + sync planning, executed as queue operations          (-> Core, VFS, Operations)
  BasilPlugins/         LuaJIT bridge, plugin manifest/loader, Lua API surface                   (-> Core, VFS)
  BasilIntegrations/    terminal launcher, viewer/editor associations (F3/F4), sound effects     (-> Core)
  BasilUI/              AppKit panes/main window, SwiftUI dialogs and settings                   (-> Core, VFS, Operations, Integrations)
Vendor/                 third-party sources + build scripts (libarchive, 7-Zip, UnRAR, libssh2, LuaJIT, BLAKE3, ...)
```

Package dependencies flow strictly downward: Core <- VFS <- everything else, and only the app target depends on all packages. Feature packages do not depend on each other except as shown. To add a dependency between packages, edit that package's `Package.swift`. To add a new package, also add it under `packages:` and the app's `dependencies:` in `project.yml`, then run `xcodegen generate`.

Key concepts:

- **VFSPath** names a location as provider + path, and paths can nest. Example: a file inside a zip on an SFTP server. Browsing an archive means pushing an `ArchiveProvider` on top of the parent provider. All pane and operation code works with `VFSPath` and providers, and never with raw `URL`/`FileManager`, except inside `LocalProvider`.
- **Providers declare capabilities** (rename, atomic rename, set permissions, server-side copy, random-access read, checksums, ...). Operations choose a strategy from those capabilities.
- **All mutating actions are Operations** that go through the single queue. This covers copy, move, delete, mkdir, rename, pack, unpack, test archive and repack after edit. The queue runs one item at a time. Items can be paused, reordered and cancelled, and each item has its own progress and log. UI code never performs file I/O directly.
- **Commands** (F-keys, menu items, command palette, Lua plugins) are registered by ID in a `CommandRegistry`, and keybindings map to command IDs. Built-in features use the same registry as plugins.
- **Built-in providers, archive backends and commands register through the same registries Lua plugins use.** New features should be addable without changing the UI module.

### Secure copy/move (critical invariant, when the "Secure copy and move" setting is on)

This fixes the ForkLift bug where only the bytes present at the start of the copy are copied.

The goal is to never read data more often than needed. Each case gets a different strategy:

| Case | Strategy |
|---|---|
| Move, same volume | `rename()`. It is instant, and no write is ever lost because writers keep writing to the same inode. |
| Copy, same APFS volume | `clonefile()`, which is instant and shares blocks. Re-check the source fingerprint afterwards and re-clone if it changed. |
| Cross-volume or remote | One pass that reads, hashes per chunk (about 1 MB) and writes into `.basil-partial-*` in the destination directory. |

After the cross-volume pass:

1. Record a source fingerprint before the pass: size, mtime, ctime and file ID. After the pass, compare it again.
   - Unchanged: the copy is done, with no re-read.
   - Changed: re-read the source and compare per-chunk hashes, then rewrite only the chunks that differ. If the file only grew, copy just the tail.
   - Then repeat the check, following the retry-then-ask policy above.
   - Chunk hashes are BLAKE3, computed on a separate task while the next chunk is read or written.
2. `F_FULLFSYNC` the file, copy metadata (xattrs, ACLs, mode, dates, Finder tags) and atomically rename it into place.
3. Optionally read back the destination and compare hashes. This is off by default and controlled by a setting.
4. A cross-volume **move deletes the source only after step 1 reports the source stable** (and after step 3 passes, if it is enabled).

Remote providers without atomic rename, random-access writes or checksums follow the same contract as closely as their capabilities allow. The queue log states when a guarantee could not be met.

Never weaken this path for speed without asking. Engine tests must include sources that are appended to, truncated and rewritten in the middle during the copy, for every strategy.

### Search index

The index works like Everything on Windows:

- **Initial scan:** APFS catalog search (`searchfs`) where available, otherwise `getattrlistbulk`.
- **Live updates:** an FSEvents stream with file-level events. Basil stores the last event ID so it can replay events missed while it wasn't running. This is the macOS counterpart of the NTFS change journal. If the history is unavailable (for example `kFSEventStreamEventFlagMustScanSubDirs`, or the volume UUID changed), rescan only the affected subtree.
- **Storage:** a custom binary format, one index per volume, memory-mapped for instant substring, wildcard and regex filename matching.
- **Searches** can run against Spotlight, the own index, or a live directory walk, and each one is an engine behind a common search protocol.

### Quick filter (current pane)

As you type, the visible pane is filtered by wildcard (`*.mp3`) or substring (`apple`). Filtering runs on the pane's loaded listing, off the main thread, and stays fast at 100k+ items. It does not change the directory or the selection on disk. VoiceOver announces the number of matches, and a visible indicator shows that a filter is active.

### Multi-rename (Total Commander style)

This is a dialog for the selected files. It offers:

- **Name and extension masks** with placeholders: `[N]` name, `[E]` extension, `[N2-5]` character ranges, `[C]` counter (start, step, digits), and date/time placeholders.
- **Search and replace**, with optional regex.
- **Case conversion.**
- A **live preview grid** showing old name and new name, with conflicts highlighted.
- **Saved presets** and **undo** of the last batch.

The batch runs as a single queue operation. It detects target collisions, resolves cycles (for example a->b, b->a) through temporary names, and writes an undo log. Lua plugins can add placeholder fields. The preview grid must be fully accessible.

### Sync (Total Commander style)

Sync compares two directories (left and right panes), optionally including subdirectories. Files are compared by date and size, optionally by content (BLAKE3), with a configurable timestamp tolerance.

- **Results:** each file is marked copy-right, copy-left, equal or different, or as existing on one side only. Filters show or hide each category, and you can flip or exclude the direction of any file.
- **Asymmetric mode:** files that exist only on the target side are deleted.
- **Stateless:** like Total Commander, sync keeps no history database, so a file that exists on one side only is offered as a copy, not detected as a deletion.
- **Execution:** sync turns into queue operations that use the secure copy engine.

### Copy engine (implemented)

- `SecureCopyEngine` (BasilOperations, `SecureCopyEngine.swift`) does the work for copy and move. `transfer(_:to:mode:)` handles a file, symlink or folder tree (existing destination folders are merged); `transferFile` does one file. It talks to its runner through `TransferMonitor` (checkpoint, log, bytes transferred, and `decide` for a source that keeps changing).
- Providers that can be written implement `WritableProvider` (BasilVFS, `ProviderIO.swift`): fingerprint, metadata read/apply, volume identifier, open for reading, create file, rename (with or without replacing), clone, remove, mkdir, symlinks, synchronize, `maxTransferChunkSize`. `LocalProvider+Write.swift` does blocking I/O on its own dispatch queue (`LocalIO`), never on the cooperative pool.
- Strategy choice: move on the same volume renames; copy on the same volume clones (falls back to streaming when the volume can't clone); everything else streams. Same volume means same provider location and equal `volumeIdentifier`.
- Stream pass: the next chunk is read while the current one is hashed (BLAKE3) and written. Later passes write only chunks whose hash changed, then truncate. Metadata is applied to the partial file, then F_FULLFSYNC, then rename; BSD flags go on after the rename.
- The engine asks `TransferMonitor.resolveConflict` when a target file exists (default: fail), and `handleError` when a step fails (default: rethrow). A move on the same volume renames per file too, also inside merged folders.
- Tests (`SecureCopyTests.swift`) use internal `EngineHooks` to change the source after a given chunk or clone and to force the stream strategy on one volume. Keep adding a test for every new strategy or provider.
- `Vendor/BLAKE3` is an unmodified copy of the official C code (see its `VERSION`); BasilOperations depends on it by path.

### Archives (libarchive and 7zz: reading and writing; UnRAR: reading; passwords)

- `Vendor/libarchive` is a SwiftPM package of unmodified upstream C sources: libarchive 3.8.11 (`CArchive`, with a `config.h` generated by its CMake on macOS), zstd (`CZstd`), lz4 (`CLZ4`) and liblzma (`CLZMA`); zlib, bzip2, iconv, libxml2 and CommonCrypto come from the SDK. Versions, checksums, what was left out and how to update are in its `VERSION`. `swift test --package-path Vendor/libarchive` round-trips every filter.
- BasilVFS `ContainerOpener` (`ContainerOpener.swift`): opens a file as a nested provider. Openers register with `ProviderRegistry.register(opener:)`; the UI only calls `registry.isContainer(item)` and `registry.openContainer(item, byContent:)`, which registers the provider under `ProviderLocation(provider:, container: file)` and returns its root. Already open containers are reused. `registry.closeContainers(keeping:)` closes the ones not in use (`MainWindowController.closeUnusedContainers`: on every folder change and once the queue has run everything; keeps pane and tab folders, `PaneModel.loadingTarget`, `TemporaryCopies.locationsInUse`; does nothing while queue items wait); a released `ArchiveProvider` removes its temporary copy.
- BasilArchives: `ArchiveBackend` (blocking: `entries(of:)` in archive order, `session(for:)` for reading data, `test`), `LibArchiveBackend`, `ArchiveIndex` (folder tree with implied folders; later entries replace earlier ones), `ArchiveProvider` and `ArchiveOpener` (the container opener; more backends go in with `register(_:first:)`, ahead of libarchive).
- `ArchiveProvider` (`capabilities` [.read, .symlinks]) conforms to `WritableProvider`, so the copy engine extracts from it (F5); its mutating calls throw `.unsupported` (changes go through `ContainerWriter`). Entry lookups check the archive file first and index it again when it changed. All libarchive work runs on the provider's serial queue. The read session moves forward through the archive and only reopens it for an earlier entry or offset, so extracting in archive order reads the archive once. Archives that are not local files (an archive in an archive) are copied to a temporary file first. A changed archive file is indexed again when listed.
- libarchive converts names through the calling thread's C locale, so `UTF8Locale.use()` sets a UTF-8 LC_CTYPE on that thread first; without it non-ASCII names come back empty.
- UI: Enter enters recognised archives (`LibArchiveBackend.archiveSuffixes`, 7z, rar), Cmd+PageDown enters any file by content, Backspace at an archive root goes to the folder holding it. `MainWindowController.ensureWritable` stops commands in a location that can't be changed, with a spoken reason (`archives: false` for Shift+F4 and Cmd+M, which do not work inside archives yet). Option+Shift+F9 queues `TestArchiveOperation` (BasilOperations, kind `.testArchive`), which goes through `ContainerOpener.test`.
- Writing: BasilVFS `ContainerWriter` (`ContainerWriter.swift`, registered with `register(writer:)`; `ArchiveOpener` is both opener and writer) with `create` (new archive) and `update` (rewrite with `ContainerChange`s: add file/folder/symlink, delete, rename). `ContainerChange.adds(for:)` expands a source tree. Both write `.basil-partial-*` next to the target (`ArchiveRewrite`: kept entries copied first with `ChangePlan` applied, then the adds read through their providers), F_FULLFSYNC, read back (every entry readable, every file present with its size), then rename into place; `update` also fails when the archive file changed meanwhile. `ContainerWriteResult.changedSources` lists sources that changed while read; the queue operations repack under the unstable-source policy.
- Formats and levels: `LibArchiveFormats` (`LibArchiveWriter.swift`). Existing archives are rewritten in their own format and filters (tar as pax restricted).
- macOS metadata: `AppleDouble` packs and unpacks extended attributes through copyfile and scratch files. Zip gets Finder's `__MACOSX/._name` entries (written by Basil), tar gets libarchive's own `._name` (mac_metadata). On reading, libarchive's seekable zip and tar readers fold those entries into the entry's mac_metadata, so they are not listed and `ArchiveProvider.metadata(of:)` returns the attributes for the copy engine.
- The pack dialog's "Test archive after packing" (remembered in `BasilSettings.packTestAfter`, off at first) queues a `TestArchiveOperation` for the packed archives once the pack item has finished.
- Queue operations (BasilOperations `ArchiveOperations.swift`): `PackOperation` (Option+F5 jobs; adds to an existing archive like TC), `ArchiveUpdateOperation` (F5/F6 into, F6 out of, F7, F8, Shift+F6 inside), `TestArchiveOperation`. UI: `PackSheet.swift`, `MainWindowController.queueArchiveUpdate`, which rereads the panes showing the archive afterwards (archives are not watched).
- Every libarchive call runs after `UTF8Locale.use()` on its thread (the queue helpers do it): a serial queue does not always run on the same thread, and without it the tar writer crashed on non-ASCII names.
- BasilArchives tests depend on BasilOperations (tests only) to extract through `SecureCopyEngine`; the library itself does not.
- Passwords: `ContainerPasswords` (BasilVFS `ContainerPasswords.swift`) in `ProviderRegistry.passwords`; the UI installs `RememberingPasswords` (memory while the app runs, then the `SecretStore`, then the prompt) with `Keychain.archivePasswords` (BasilCore `Keychain.swift`, generic passwords found by the archive's path, "outer.zip > /inner.7z" for nested ones; UI tests use `MemorySecretStore`). The prompt is an NSAlert sheet (`PasswordPrompt.swift`): secure field "Password", "Remember in Keychain" (off, saved only once the password worked), "Wrong password for X. Try again." on a retry. Backends take `password:`; names that are encrypted throw `.passwordNeeded` / `.wrongPassword` from `entries`, and `ArchiveOpener.list` asks until one works. For encrypted entries, `ArchiveProvider.knownPassword()` asks once (reads waiting at the same time share one prompt) and checks the password with `checkPassword` before any data is handed out (7z: test the first encrypted file; libarchive: read one byte, which checks zip's verifier); a cancelled prompt fails with `.noPassword` and the next read asks again. Encrypted libarchive archives (zip) are not changed yet (`updateRefusal`); 7z ones are, with the known password.
- Writing 7z (`SevenZipWriter.swift`): `ArchiveOpener` routes `create` for 7z, and for zip with a password (AES-256 only), to `SevenZipWriter` once the 7-Zip backend is registered (`packFormats` then lists 7z second and zip with `encryption`), and `update` of a 7z archive. Pack options: level (Store 0, Fast 1, Normal 5, Maximum 7, Ultra 9), `-ms` solid, `-p` (password on stdin) and `-mhe=on` for encrypted names. Fast path (`FastPlan`): when every add is a local file at the same relative path as in the archive, 7zz runs in that folder with `-i@` the top-level names (it always takes a listed folder whole) and `-x@` everything under them not to be added; otherwise the adds are staged in a ".basil-partial-*-stage" folder next to the archive (clonefile on the same volume, else copied through the provider, dates and permissions applied). Changes to an existing 7z never touch it: `d`, `rn` (by stored name, every entry under a folder) and `a` each write a changed copy with `-u-` and `-up1!new` / `-up1q1r2x2y2z2w2!new`; an encrypted one gets its password twice (7zz asks to open and for the new items), and keeps `-mhe` when its names were encrypted. The result is F_FULLFSYNCed, tested and listed (7zz for 7z and encrypted zip) against the expected paths and sizes, then renamed into place; a source whose fingerprint or size changed is reported in `changedSources`. Unreadable sources are asked about (Retry / Skip) before 7zz runs. Zip files libarchive cannot read (an AES-encrypted link, other methods) fall back to `SevenZipBackend.zipFallback()`, registered after libarchive: `ArchiveOpener.open` tries the next backend when one reports `.damaged`. The pack dialog shows Solid archive (remembered, on), Password with Show password, and once a password is typed Encrypt file names (remembered, off) and Remember in Keychain (off); after packing the password is kept in memory (`RememberingPasswords.remember`), so opening or testing the new archive does not ask. Pipe readers run on their own threads (`SevenZipTool.thread`), never GCD work items: callers wait for them while holding GCD threads, and parallel tests starved the pool and hung; pipe ends are close-on-exec at once.
- 7z (`SevenZipBackend.swift`, `SevenZipTool.swift`): read through the 7zz tool built from `Vendor/7zip` (unmodified 7-Zip sources; `Vendor/7zip/build.sh` builds into `Vendor/build/7zip/7zz`; the app target's "Build 7zz" phase runs it, and "Copy and sign 7zz" puts it in Contents/MacOS signed with the app's identity; `SevenZipBackend.bundled()` finds it). Registered ahead of libarchive, only for 7z (`-t7z`). Listing is `l -slt -ba` run with TZ=UTC; data is one `x -so` process per session that writes every file from the requested one on (selected with an `-i@` list file and `-spd`), so reading forward decompresses once; each file's CRC is checked as its last byte is read, because 7zz writes damaged data to stdout anyway. Symlink targets (stored as data) are read while listing. 7zz runs through `posix_spawn`/`waitpid` (Process.waitUntilExit hung), with only fds 0-2 inherited. 7zz reads a password as one line from stdin when it asks, so it goes into the stdin pipe, never on argv; with no password stdin is closed and 7zz stops. Never pass `-bso1` with `-so` (messages would mix into the data). `ArchiveProvider` closes a read session after 10 s without reads (it may hold a 7zz process). The tests build 7zz if it is missing.
- RAR (`UnRARBackend.swift`): read only, through the UnRAR library linked in from `Vendor/unrar` (unmodified UnRAR 7.2.7 sources as the SwiftPM C++ target `CUnRAR`, the `dll.hpp` API; see its `VERSION`). `ArchiveOpener` has it by default, ahead of libarchive. Listing uses RAR_OM_LIST (a file split over volumes is listed once); a later volume ("name.part3.rar", "name.r00") is mapped to the first one next to it (`firstVolume(of:)`). Data comes from a `RarProducer` thread per session that runs RAR_TEST over the wanted entries in archive order and writes into a pipe, holding each file's last piece back until UnRAR has checked its CRC32 or BLAKE2, so damaged data or data decrypted with a wrong password never reaches a copy's end. RAR 4 Unix symlinks keep their target as data, so listing extracts them into a scratch folder and reads them back; hard links and file copies point `dataOrdinal` at their source. Passwords go through the library's callback (never a process or argv); RAR 5 checks a password before unpacking, RAR 4 by unpacking the first encrypted file. Dictionaries over 4 GB are refused (UCM_LARGEDICT). UnRAR keeps its error state in a global `ErrHandler`; `Vendor/unrar/Package.swift` defines it as a call to a thread_local handler in `BasilErrors.cpp`, and `RarHandle` calls `BasilUnRARClearErrors()` before each header and file call (otherwise one failure fails every later call, and parallel archives see each other's errors). A `RarHandle` is opened and used on one thread. `updateRefusal` says RAR archives can only be read. Tests (`RARTests.swift`) read libarchive's RAR test archives in `Tests/BasilArchivesTests/Fixtures/RAR` (see its README; nothing on macOS makes RAR archives).

### File lists (.lst, implemented)

- Like TC's DiskDir plugin: a list of a folder tree (names, sizes, dates, permissions, link targets) browsed later like a folder. BasilArchives `FileListFormat.swift` (formats) and `FileList.swift` (`FileListProvider`, `FileListOpener`, provider ID `filelist`, registered in AppDelegate as opener and writer).
- Two pack formats in the pack dialog (Option+F5), both written as `.lst`: "Optimised file list (lst)" (id `lst-optimised`, binary: magic `BASILLST`, parent indices instead of full paths, little-endian, `END!` marker) and "File list, text (lst)" (id `lst`, UTF-8 `# Basil file list 1`, tab-separated, ISO UTC dates, escaped paths). DiskDir's text format is also read (root on the first line, backslashes, `yyyy.m.d` `h:mm.ss` local time, UTF-8 or Windows-1252), only for files named .lst. Content decides the flavour. Written through a partial file, F_FULLFSYNC, read back and compared, renamed into place.
- `FileListProvider` has no capabilities (no `.read`): `totals(of:)` (Cmd+Shift+S) works from the listed sizes; everything else throws `.unsupported`, and `updateRefusal` refuses every change. The UI checks `MainWindowController.ensureReadable` (no `.read` and no `.write`) before F5/F6, F3, F4, pack and checksums and says "X is a file list ...". `PackFormat.storesContents` false hides "Move to archive"; `PackFormat.fileExtension` lets two formats share an extension.

### Split and combine (implemented)

- BasilOperations `SplitOperations.swift`: `SplitFileOperation` (kind `.split`) writes "name.ext.001", ".002", ... (at least 3 digits, more for 1000+ parts) through partial files, with optional "name.ext.sfv" (`; Split by Basil from`, `; original-name=`, `; original-size=`, `; original-crc32=` comments plus one `part CRC` line per part, so Verify Checksums also works on it). A source that changed while split is split again (unstable-source policy). Leftover higher-numbered parts and a stale Basil SFV from an earlier split are removed.
- `CombineFilesOperation` (kind `.combine`): `parts(of:)` finds the set from any part or the .sfv / .crc (consecutive numbers from 1, every part the SFV lists); each part's CRC32 is checked while read, the result's size and CRC32 at the end; a mismatch removes the result. TC's `name.crc` (`filename=`, `size=`, `crc32=`) is read too, and its `filename=` names the result.
- `SplitSizes`: presets with exact media sizes (CD 650/700/800 MB, DVD 4.7 GB, DVD DL 8.5 GB, Blu-ray 25/50 GB, FAT32 4 GB minus 1) and `parse("1.5 GB", decimal:)` (a unit is required; binary or decimal base from the dialog's Units pop-up).
- UI (`SplitCommands.swift`): Files > Split > Split File... (cursor file, SwiftUI sheet: target folder, Part size pop-up, Custom size and Units when custom, Create SFV file, a summary of the parts) and Combine Files... (cursor part, a text sheet with the result path; an existing file asks Replace). Choices are remembered in `BasilSettings.split*`. No default keys.

### Checksums (implemented)

- BasilOperations `Checksums.swift`: `ChecksumAlgorithm` (CRC32 via zlib, MD5, SHA-1, SHA-256/384/512 and SHA3-256/512 via CryptoKit, BLAKE3 via `Vendor/BLAKE3`, XXH3 and XXH128 via `Vendor/xxHash`), `ChecksumHasher`, and `ChecksumFile` (writes `hash  name`, SFV `name HASH` with a `;` comment, XXH3 with xxhsum's `XXH3_` prefix; reads those plus `hash *name`, BSD `SHA256 (name) = hash` and comments). Extensions: sfv, md5, sha, sha256, sha384, sha512, sha3-256, sha3-512, blake3, xxh3, xxh128 (also read: sha1, b3, crc, crc32). Without a known extension the algorithm comes from BSD tags or the hash length.
- `ChecksumOperations.swift`: `CreateChecksumsOperation` (one file for all, names relative to the current folder with `/`, folders walked; or `.perFile`, `name.ext` next to each file; written through a `.basil-partial-*` file renamed into place; unreadable files are left out, logged, and fail the item) and `VerifyChecksumsOperation` (logs each file that does not match, is missing or can't be read; fails with "2 of 12 files failed"). Kinds `.createChecksums` and `.verifyChecksums` (BasilCore).
- UI (`ChecksumCommands.swift`): Files > Checksums. Create asks with an NSAlert sheet: Algorithm pop-up (last used, `BasilSettings.checksumAlgorithm`, SHA-256 at first), "One checksum file per file", and the file name (`item.ext` for one item, else `folder.ext`; the extension follows the algorithm). An existing single file asks "Replace it?". Verify works on the selected or cursor checksum files. No default keys (TC has none).
- `Vendor/xxHash`: official xxhash.c/xxhash.h 0.8.4, unmodified (see its `VERSION`), with a small Swift wrapper `XXH3Hasher`; `swift test --package-path Vendor/xxHash`.

### Panes (implemented in BasilUI)

- **State and async work:** `PaneModel` (one per pane) owns the directory, sorted `allItems`, visible `rows` (hidden files and the filter applied), the `selected` set and the sort order. Listing, sorting and filtering run in detached tasks. Every async result is checked against a generation counter, so stale results from an older keystroke, sort or load are dropped. Keep this pattern for anything async that writes model state.
- **Navigation:** there is no ".." row. Backspace or Cmd+Up goes to the parent folder, and the cursor lands on the folder you came from.
- **Selection:** the user-facing word is "selected", never "marked". The cursor is the table's single selection; selected items (Total Commander "marking") are separate, in `model.selected`, and drawn in the selection colour.
- **Keys:** `PaneTableView.keyDown` turns the event into a `KeyChord` and tries `CommandRegistry` first. Command-key chords are also tried in `performKeyEquivalent`, so registry bindings beat menu items, including the standard Window menu items AppKit adds by itself (its Minimize takes Cmd+M). Plain printable characters are type-ahead. Commands and their default keys live in `BuiltinCommands.swift`. Function and navigation keys keep their raw key code; other keys bind on the unshifted character (Cmd+Shift+. is `.character(".")` with `.shift`).
- **Default keys:**
  - Tab switches pane. Enter or Cmd+Down opens. Backspace or Cmd+Up goes to the parent folder.
  - Home and End (Fn+Left/Right on Mac keyboards) jump to the first or last item. They are not in the menus: VoiceOver reads a menu item's title when its key is pressed.
  - F2 rereads. Cmd+Shift+. toggles hidden files. Cmd+S opens the quick filter. Option+I reads the status bar. Cmd+I opens the Info sheet.
  - Cmd+G (or Cmd+Shift+G) goes to a folder or file (`GoToSheet.swift`): a sheet with a path field and a suggestion list for the last path part (prefix matches first, then names containing the text, no case; hidden items such as /Volumes once something is typed, dot files only after a dot). Up/Down pick, Tab completes (folders get a slash), Return goes; a file opens its folder with the cursor on it. The number of suggestions is announced once typing pauses, and only when it changes.
  - Finder Go keys in the current pane: Cmd+Shift+H Home, Cmd+Shift+D Desktop, Cmd+Shift+O Documents, Cmd+Option+L Downloads, Cmd+Shift+A Applications, Cmd+Shift+U Utilities, Cmd+Shift+I iCloud Drive, Cmd+Shift+C /Volumes.
  - Cmd+Shift+S calculates the size of the folders among the selected (or cursor) items, like TC; the Size column then shows it (spoken "dir, 1.5 MB"), the status bar counts it, and the result is spoken ("Alpha, 1.5 MB, 120 files, 8 folders"; "Calculating" only after a second). Sizes stay until the pane shows another folder (`PaneModel.folderSizes`). The walk is `FileSystemProvider.totals(of:)` (BasilVFS, `DirectorySize.swift`): symlinks not followed, unreadable subfolders counted and skipped.
  - Cmd+D opens the locations menu for the current pane, Cmd+F1 for the left pane, Cmd+F2 for the right.
  - Space selects or deselects. Shift+Up/Down selects while moving. Cmd+A or Cmd+Numpad Plus selects all files. Cmd+Numpad Minus or Cmd+Shift+Minus deselects all (`KeyChord.Key.numpad` keeps keypad keys apart from the main keys).
  - Numpad keys like TC (`SelectionCommands.swift`): Numpad Plus / Minus open Select Group / Deselect Group (a sheet with a mask in quick-filter syntax, a shared history of 20 masks and "Include folders", off by default; both remembered in the pane-state defaults), Numpad Multiply inverts the selection of the files (selected folders stay), Numpad Divide restores the selection from before the last bulk change (select or deselect all, a group, invert, the clearing after an operation; by name, so it also works in another folder), Option+Numpad Plus / Minus select / deselect every file with the cursor file's extension. Speech is the same as for Space; nothing matching says "No matching items". Laptops without a keypad reach them through the Mark menu or remapping.
  - Ctrl+Shift+F1 Brief view, Ctrl+Shift+F2 Full view, Ctrl+Shift+F3 to F6 sort by name, extension, date and size, Ctrl+Shift+F7 unsorted, Ctrl+Shift+F8 to F12 custom views 1-5 (6-9 have no default key). The active sort key again reverses the order. Changes are spoken ("Sorted by extension, descending", "Unsorted", "Full view"). Unsorted (`SortKey.unsorted`) is the provider's listing order with folders first; choosing it lists the folder again, and new items go last in their group. Option+F keys are actions (Option+F5 pack).
  - Cmd+, opens Settings, Cmd+W closes it (only the settings window: the main menu has no Close item, so Cmd+W never closes the main window). Cmd+J opens or closes the operation queue panel.
  - F5 copy and F6 move (sheet with the target path, prefilled with the other pane; relative paths and ~ work), Shift+F6 rename (sheet, name without extension preselected; with more than one item selected it opens Multi-Rename), Shift+F4 new file (sheet prefilled with the cursor file's name; an existing file is just opened; otherwise `NewFileOperation` creates it, rw-r--r--, then it opens in the editor), F7 new folder, F8 or Forward Delete moves to the Trash, Shift+F8 or Shift+Forward Delete deletes permanently. Each confirms in a sheet and runs in the queue. Without items they say "No items".
  - F3 Quick Look, F4 edit, Cmd+Shift+T opens a terminal in the current folder (see "F3 / F4 / terminal").
  - Cmd+M opens the Multi-Rename tool.
  - Shift+F10 (or VO+Shift+M, or a right click) opens the context menu of the cursor item.
  - Enter on an archive (or a .lst file list) enters it; Cmd+PageDown enters any file whose content is an archive; Option+F5 packs; Option+F9 unpacks; Option+Shift+F9 tests the selected or cursor archives.
  - Cmd+I opens the Info sheet for the cursor item (`InfoSheet.swift`, SwiftUI in a sheet; Escape or Return closes): name, kind, size (folders calculated), where, dates, permissions, owner, and for files an Open with picker plus "Use for All .ext Files", which sets the system default app for that type (`FileAssociations`, BasilIntegrations).
- **Tabs** (`PaneTabs.swift`): each pane has folder tabs (`PaneTab`: folder, cursor, custom name, lock, sort, view). The pane keeps one model; switching a tab saves the live state into the old tab and loads the new one (view and sort applied without speech, then "Tab 2 of 3, Downloads" is spoken). The tab row (`TabBar`, a tab group of radio buttons labelled "Left pane tabs") shows only with two or more tabs; a locked tab reads "Downloads (locked)". Keys: Cmd+T new tab (current folder, after the current tab), Cmd+W close tab (never the last: "This is the only tab"), Ctrl+Tab / Ctrl+Shift+Tab next / previous (wrapping), Cmd+1-9 go to a tab, Cmd+Option+Up opens the cursor folder in a new tab; Duplicate (keeps name and lock), Close Other Tabs, Rename Tab (empty name = folder name) and Lock Tab are in the Tabs menu. Columns come from `ColumnCatalog` (BasilCore), which plugins can extend. Each `ColumnDefinition` gives the display text and optionally different spoken text.
  - The Name column always shows the full name with extension. Ext is an optional column (in Full, hidden); `BasilSettings.viewsVersion` 2 hid it once in saved Full views.

- **Settings:** `SettingsStore` (BasilCore, `@Observable`) is persisted as JSON in UserDefaults and is tolerant of missing keys. AppKit code observes it with `onChange`. It holds size format (unit and 1024/1000 base), date format (pattern plus time format), views, the go-to-root-on-volume-switch flag, and bookmarks. The Settings window is SwiftUI (`SettingsWindow.swift`), with Move Up/Down buttons and also VoiceOver actions for reordering.
- **Locations menu:** an NSMenu listing Home, volumes, bookmarks, "Add Current Folder to Bookmarks" and "Manage Bookmarks...". Choosing a volume restores the last folder visited on it (per pane) unless the go-to-root setting is on.
- **VoiceOver speech rules (the user asked for minimal chatter):**
  - The lists are labelled only "Left pane" / "Right pane". Nothing is announced on Tab or on a folder change; VoiceOver reads the item under the cursor.
  - Rows read like Total Commander columns: "test, dir, date, ..." or "song.mp3, 1.5 MB, ...". No "file" or "folder" word is added. A selected item's name reads "song.mp3, selected".
  - Space says "Selected, 2 items", "Deselected, 1 item", or just "Deselected" when nothing is left selected.
  - `PaneTableView` exposes its own accessibility rows and cells (`PaneRowElement`, `PaneCellElement`) instead of NSTableView's, built from the model through `PaneViewController.paneTable(_:spokenTextForRow:column:)`. Cells with no text (a folder's empty extension) are left out: NSTableView's own empty AXCell made VoiceOver say "column 2, row 1". Each row's label is its non-empty cells joined with commas, and its role description is empty (no "table row" suffix). Right after the list gets focus (Tab), the table is the focused element, so VoiceOver reads "Right pane, table, row 1 of 3, ..."; from the first cursor move on, the cursor row is the focused element (`accessibilityFocusedUIElement`, plus a focus-changed notification on every selection change), so Up/Down reads the whole row. Without this, VoiceOver put its cursor on the Name cell after Tab and read only names. VO+arrows still moves between cells. Only the visible rows and the cursor row are exposed.
  - The path header is a path bar (`PathBar.swift`): a group labelled "Path" whose value is the whole path, with one button per part (the volume, "Macintosh HD" or the volume under /Volumes, then each folder; inside an archive the archive's own folders, the archive, then its inner folders). Clicking or VO+Space goes to that part with the cursor on the folder leading back (like Backspace), and works when the current folder was deleted. Cmd+L (`pane.focusPath`) focuses the last part; Left and Right move, Return or Space go, Escape or Tab return to the list. Separators are drawn lines (`PathSeparator`), not text, so VoiceOver skips them. The parts scroll, so long paths keep every part reachable.
- **Colours** are drawn in views (`ThemedBox`, row views), not set as layer `cgColor`, so light/dark switches apply immediately.

### Operation queue (implemented)

- `FileOperationQueue` (BasilOperations, `@MainActor @Observable`) is the single global queue, created in `AppDelegate` and owned by `MainWindowController`. It lives in memory only and does not survive restarts. Operations conform to `QueueOperation` (`title`, `run(_ context:) async throws`). `run` executes off the main actor and must call `context.checkpoint()` often: it waits while the item is paused and throws `CancellationError` once it is cancelled. `context.progress(fraction, detail)` is throttled to about 10 updates a second; `context.log` appends to the item's log.
- Items run one at a time and a new item starts right away when the queue is idle. Pausing the running item holds the queue; a paused waiting item is skipped until resumed. Removing the running item cancels it and drops it once it has stopped. Finished, failed and cancelled items stay in the list (with their log) until "Remove Finished".
- Queue events (finished, failed, cancelled) are announced through `MainWindowController.announce`, which posts on `NSApp` so they are heard while the queue panel is key.
- The queue panel (`QueueWindow.swift`) is a floating `NSPanel` hosting SwiftUI. In its list: Space pauses or resumes, Cmd+Up/Down move, Delete cancels and removes. Escape or Cmd+J (whatever is bound to `queue.show`) closes it. Each row is one static-text element ("Copy ..., running, 45 percent, 12 of 40 files") with VoiceOver actions for the same commands.
- Operations declare a `kind` (`OperationKind`, BasilCore) and report `context.items(done:total:)`; `QueueEvent` carries kind, outcome, counts and reason, and `MainWindowController.handle` turns it into sound and speech (`EventFeedbackPlayer`, BasilIntegrations).
- Operations ask questions with `context.ask(.conflict / .unstableSource)`; the queue marks the item "waiting for your decision", sends a `.needsDecision` event and calls `promptHandler` (the UI shows an NSAlert sheet on the main window). Conflict choices are Total Commander's: Overwrite, Skip, Overwrite All Older, Overwrite All, Skip All, Rename ("name (2).ext"), Cancel; "All" answers last for the rest of the operation.
- File operations (`FileOperations.swift`): `TransferOperation` (counts bytes first, progress by bytes), `DeleteOperation` (Trash through the provider's `.trash` capability, or recursive remove), `MakeDirectoryOperation`, `RenameOperation` (a change of case only is allowed). `QueueItem.whenDone` lets the UI put the cursor on a new folder or renamed item.
- When one item of a copy, move or delete fails, the operation asks `.itemFailed` (Total Commander's Retry / Skip / Skip All / Cancel; Skip All lasts for the rest of the operation). `ItemErrorPolicy` (FileOperations.swift) asks and remembers; the engine calls `TransferMonitor.handleError` per step (file, symlink, folder create/list/metadata/remove) and lists skipped failures in `TransferSummary.failed`. A skipped item keeps its source on a move, and the folders above it. Without a prompt handler (tests) the operation fails as before. New folder and rename still just fail.
- Progress window (`ProgressWindow.swift`, `ProgressWindowController`), TC's progress dialog: the queue calls `onItemStarted` / `onItemStopped`; the window follows the running item (title, status "45 percent" / "Paused" / "Waiting for your decision" / "Cancelling", detail, bar, "2 more waiting") with Background (Return), Pause/Resume and Cancel (Escape). It opens at once and takes focus for `immediateKinds`, after 1 s for the rest; a backgrounded item stays hidden; hiding gives focus back to the pane; `promptAnswered` refocuses it after a prompt sheet. Not shown while the queue panel is open or with `BasilSettings.showProgressWindow` off (UI tests: off unless `BASIL_UITEST_PROGRESS=1`). Accessibility sees it as a dialog (`app.dialogs["Test operation 1"]`).
- Debug builds have a "Debug" menu with "Add Test Operation" (a 10-second fake operation in `App/Sources/DebugMenu.swift`), used by `QueueUITests`.

### Multi-rename (implemented)

- Rules live in BasilCore (`MultiRename.swift`): `RenameRule` (name and extension masks, search and replace with optional regex and case sensitivity, case conversion, counter start/step/digits), `MultiRename.newName`, and `MultiRenamePreview.make`, which flags empty names, slashes, duplicates within the batch and clashes with items outside the batch (names compared without case). Placeholders: `[N]`, `[E]` with ranges (`[N3]`, `[N2-5]`, `[N2-]`, `[N2,3]`, `[N-3-]`, `[N2--2]`), `[P]`, `[G]`, `[C]` and `[C10+5:3]`, `[Y] [y] [M] [D] [h] [m] [s]` (modification date), and `[=name]` for placeholders registered in `MultiRenamePlaceholders` (plugins). `[[` and `]]` are literal brackets; unknown placeholders stay as typed. Names split into name and extension like the Ext column (`FileItem.nameAndExtension`: folders have no extension). Order: masks, then search and replace, then case.
- `MultiRenameOperation` (BasilOperations) runs the batch in the queue. Items whose target is the current name of a batch item (swaps, case-only changes) first get a temporary `.basil-rename-*` name; a failure asks Retry / Skip / Skip All / Cancel, and a skipped or cancelled item goes back to its old name. The renames done are written to the undo log (`LastMultiRename.json` in `MainWindowController.dataDirectory`, Application Support/Basil; UI tests use a temp folder). `MultiRenameOperation.undo(log:)` builds the reverse batch and removes the log when it has run.
- The window (`MultiRenameWindow.swift`, SwiftUI) is modal (`NSApp.runModal`), so accessibility sees it as a dialog (`app.dialogs` in UI tests). Focus starts in the name mask; Return starts, Escape closes. The Undo button is only in the tool. Presets are saved in `BasilSettings.renamePresets`. The preview is an AppKit `NSTableView` (`RenamePreviewTable`) with Old name, New name, Status ("Will be renamed", "Unchanged", "Problem: ...") and Modified columns; SwiftUI's `Table` put unlabelled groups in its cells that failed the audit. Start is disabled while there are problems.

### Large directories

Panes use view-based `NSTableView` with cell reuse. Listing is streamed off the main thread (`getattrlistbulk` for local volumes), and sorting and filtering happen off the main actor. Updates come from FSEvents and are applied as diffs, not full reloads. Never load the whole directory in memory more than once, and never compute anything per-row on the main thread.

### Remote connections (SFTP and FTP/FTPS implemented)

- BasilVFS `RemoteConnector.swift`: `RemoteConnector` (a service: `connect(_ target:, prompts:)` returns a provider and start folder; `knownHosts()` for suggestions), `RemotePrompts` (the UI's side: `hostKey`, `secret`, `secretWorked`, `note`), `ConnectedProvider` (`connectionTitle`, `homeDirectory`, `disconnect`), `RemoteCancelled`. `ProviderRegistry.register(connector:)`, `connect(_:prompts:)` (reuses an open connection with the same location), `openConnections`, `disconnect(_:)` (also drops containers opened inside it). `RemoteTarget` (service, host, port, user, path, authentication; `parse("user@host:port/path")`, `address`) and `SavedConnection` live in BasilCore (`RemoteTarget.swift`), saved in `BasilSettings.connections`.
- `Vendor/libssh2`: libssh2 1.11.1 and OpenSSL 3.5.9 (no test/ or demos/), unmodified; `build.sh` builds libcrypto and libssl (arm64 asm) and libssh2 into `build/LibSSH2.xcframework` (one static library, module `CLibSSH2`, links zlib; the `CBasilTLS` target reads OpenSSL's headers from `build/openssl/include`), which the package wraps as a binary target. It must exist before SwiftPM or Xcode resolve packages: run `scripts/bootstrap.sh` after cloning. See its `VERSION`.
- BasilRemote: `SSHConnection` (socket with connect timeout, SO_NOSIGPIPE; handshake with host key algorithms of known key types first; agent, key file, password and keyboard-interactive logins; SFTP channel; keepalive every 30 s). Every libssh2 call runs on the connection's own serial queue (blocking mode, 60 s timeout), never on the cooperative pool. A broken connection is torn down and the next call reconnects without asking, with the accepted host key (a different key fails) and the login that worked (kept in memory). Handles from an older connection fail ("connection was lost while X was open").
- `SFTPConnector` (service `sftp`, port 22): ~/.ssh/config (`SSHConfig`: Host patterns with negation, first value wins, IdentityFile collects with %-tokens and ~, Include, Match skipped; ProxyJump, ProxyCommand, forwards and CertificateFile are reported through `note`), host key check against ~/.ssh/known_hosts (`KnownHosts`: plain, hashed `|1|`, wildcards, `[host]:port`, `@revoked` refuses, `@cert-authority` skipped; accepting adds one line or replaces the single-host line of that key type, through a temp file), then logins in ssh's order: agent (unless IdentitiesOnly), configured IdentityFiles or the default id_ed25519 / id_ecdsa / id_rsa (passphrase asked for encrypted ones, 3 tries), password, keyboard-interactive (password prompts get the password; other questions are asked). Keychain keys: `sftp:user@host[:port]` and `ssh-key:/path` in `Keychain.remoteSecrets`.
- `SFTPProvider` (location `sftp` / `user@host[:port]`): capabilities read, write, random access, rename, atomic rename, permissions, dates, symlinks (no trash, clone or watch). Writes go to the copy engine's partial file, `fsync@openssh.com` (a server without it is not an error), permissions and dates by fsetstat, then `posix-rename@openssh.com` (fallback: remove and rename). OpenSSH's plain "failure" status is turned into alreadyExists, directoryNotEmpty and notADirectory by checking the path. `createSymlink` passes target first (OpenSSH's order). `volumeIdentifier` uses statvfs's fsid. Fingerprints have size and whole-second mtime only, so a remote source rewritten at the same size within one second is not seen as changed.
- UI (`RemoteConnections.swift`): Cmd+K (`net.connect`) opens the manager sheet: Address field with Quick Connect, the saved list (Return or Connect; VoiceOver actions Connect, Edit, Move Up, Move Down, Delete), New, Edit, Duplicate, Delete, Close. The editor replaces the list in the same sheet (Name, Protocol when there are several services, Host, Port, User, Start folder, Log in with, Key file with Choose Key File); Escape goes back. `RemotePromptsUI` asks with NSAlert sheets: unknown host (Trust and Remember / Trust Once / Cancel), changed key (critical; Cancel first, Connect Once, Replace Key and Connect), password or passphrase with Remember in Keychain (a stored secret is tried first). Connecting reports in the pane, says "Connecting to X" after 1 s, then "Connected to user@host". Net menu: Connect to Server, Disconnect (the active pane's connection, "Disconnect user@host"), then saved connections 1-20 by name (`net.saved1`...). Disconnect sends panes and tabs inside the connection to the home folder. The locations menu (Cmd+D) lists open connections. Remote panes reread whenever a queue item stops (`rereadRemotePanes`). F8 on a server deletes permanently (no Trash) after the warning.
- Connectors describe their editor (`RemoteConnector.logins`, `automaticLoginTitle`, `hostPlaceholder`, `userPlaceholder`, `options: [RemoteOption]`); option values live in `RemoteTarget.options` (string keys, only values that differ from the default are saved). The UI has no per-service code. `RemotePrompts.certificate(_:)` asks about TLS certificates (`CertificateQuestion`, NSAlert sheet `askCertificate`).
- FTP (`FTPConnector`, registered three times: `.plain` service `ftp`, `.explicitTLS` `ftpes`, `.implicitTLS` `ftps`, FileZilla's schemes): `FTPSocket` (blocking BSD socket with timeouts; TLS through `CBasilTLS`, a small C API over libssl in `Vendor/libssh2/TLS`), `FTPSession` (one control connection on its own serial queue: replies, USER/PASS, FEAT, OPTS UTF8, PBSZ/PROT P, TYPE I, EPSV then PASV with a private PASV address replaced by the server's, or EPRT/PORT in active mode; data TLS resumes the control session and its handshake watches the control connection so a refusal does not hang), `FTPPool` (up to 4 sessions, lowered on 421; NOOP after 30 s idle; a dead idle session is replaced once), `FTPProvider` (MLSD/MLST, or CWD + LIST [-a] with Unix and DOS parsers in `FTPListing` plus MDTM/SIZE; RNFR/RNTO, DELE then rename when replacing fails; MFMT and SITE CHMOD; no symlink creation, no clone, no fsync). `FTPWriteFile` is one STOR from offset 0 (no random writes: the engine rewrites the partial file whole when the source changed; the upload ends with close_notify, shutdown and a drain, then 226). `FTPReadFile` is one RETR, restarted with REST on a jump; a 451 at the end of a file that shrank counts as its end. `FTPTrust`: SecTrust with the host name first, then fingerprints in the trust file; later sessions accept only the system-trusted or the accepted certificate. Keychain key `ftp:user@host[:port]`. An empty user is anonymous.
- Tests: `Packages/BasilRemote/Tests` start macOS's own sshd (`/usr/sbin/sshd -D`, as the user, `UsePAM no`, `PerSourcePenalties no`, internal-sftp) and an ssh-agent on free ports with throwaway keys, killed at exit; the server serves this Mac, so results are checked with FileManager. The copy-engine tests cover upload with a local source appended, truncated and rewritten, and download with a remote source appended, truncated and rewritten after a second. FTP tests (`FTPTests.swift`, `FTPTestServer.swift`) start pure-ftpd from `build/test-ftpd` (built by `scripts/build-test-ftpd.sh`, which they run when missing; needs Homebrew) on free ports: plain/explicit and implicit, a self-signed localhost certificate, a virtual account without chroot; `ignoreModernListing` makes the client use LIST. Logins take about a second (pure-ftpd's argon2). UI test `testFTPSConnectBrowseAndDisconnect` passes `BASIL_UITEST_FTPD` (`UITestFTPServer`) and is skipped when the server is not built. UI test `testSFTPConnectBrowseAndDisconnect` uses the Debug fixture `BASIL_UITEST_SSHD=1` (`UITestSSHServer`): the app starts sshd with a watchdog that stops it when the app dies, registers an `SFTPConnector` with a fake home and known_hosts, and saves "Test server".

### Dropbox (implemented)

- `Vendor/SwiftyDropbox`: the official SDK 10.2.4, unmodified (see its `VERSION`), a SwiftPM dependency of BasilRemote (Swift 5 mode, imported `@preconcurrency`). Basil uses its generated routes and `DropboxClient` only; sign-in, token storage and downloads are Basil's own. `DropboxConnector` calls the SDK's `setAssertFunc` with a no-op: the SDK's validators use `precondition`.
- App key: `BASIL_DROPBOX_APP_KEY` in `Config/Dropbox.local.xcconfig` (gitignored, included by `Config/Base.xcconfig`), put into Info.plist as `BasilDropboxAppKey` and the URL scheme `db-<key>`. Without a key AppDelegate registers no Dropbox connector. The App Console app is Scoped access, Full Dropbox, with the five scopes in `DropboxScopes` (account_info.read, files.metadata.read/write, files.content.read/write). `db_privacypolicy.md` (repo root) is the privacy policy for Dropbox's production review: keep the code to what it promises (no background access, tokens only in the Keychain as `dropbox:<account id>`, deleting a connection revokes).
- `DropboxAuth.swift`: OAuth 2 code flow with PKCE (S256, `token_access_type=offline`, redirect `db-<key>://2/token`, no app secret), token exchange, refresh, revoke (`auth/token/revoke`). `DropboxRedirects.handle(url)` is called from `AppDelegate.application(_:open:)` and resumes the sign-in waiting for that `state`. `DropboxTokens` is the SDK's `AccessTokenProvider` and refreshes five minutes before expiry (one refresh at a time); `expire()` after a 401.
- `DropboxConnector` (service `dropbox`, `usesServerAddress` false): a saved target holds the account ID in `host` and the email in `user` after sign-in (`ConnectedProvider.signedInTarget`, which `MainWindowController.connect(_:saved:)` writes back to the saved connection). A stored refresh token connects without the browser; `invalid_grant` removes it and signs in again. The browser sign-in runs `RemotePrompts.browserSignIn` (UI: `waitForBrowserSignIn`, an NSAlert sheet with Cancel and Open Browser Again that ends when the redirect arrives) against `DropboxRedirects.wait`. `forget(_:remaining:)` (deleting a saved connection; the UI disconnects that account first) revokes and removes the token unless another saved connection has the same account.
- `DropboxProvider` (location `dropbox` / the account's email): capabilities read, write, random-access read, rename, set dates (only at upload), clone (server-side `copy_v2`), trash (`delete_v2`, restorable on dropbox.com; F8 and Shift+F8 both use it). Fingerprints carry the revision (as `fileID`) and server_modified, so any change to a source is seen. Reads (`DropboxReadFile`) are Basil's own ranged POSTs to `files/download` pinned to the revision current at open (`rev:`), 8 MiB windows with the next one prefetched; `Dropbox-API-Arg` JSON is ASCII-escaped (`headerJSON`). Writes (`DropboxWriteFile`) are sequential: parts of 8 MiB through `upload_session/start` and `append_v2`, each with its `content_hash` (`DropboxContentHash`); the commit (`upload` for small files, `upload_session/finish`, mode add, client_modified from `apply`) happens in `apply(_:)` (after the last write in both copy modes, so its error is thrown) or `synchronize()`. A file closed before that is never committed; `remove` of such a never-committed partial just forgets it (`uncommitted`). `remove` refuses a folder that is not empty (Dropbox would delete it whole). Replacing rename deletes the target first (not atomic). Case-only renames go through a temporary name when Dropbox refuses them. Errors are mapped from the route's `error_summary` (`DropboxFailure`), with retries for rate limits, server and network errors and an expired token.
- UI tests always have a Dropbox connector (key "uitest" when the build has none) and never open the browser (`MainWindowController.opensBrowser`); `testDropboxConnectionEditorAndSignInSheet` audits the editor and the sign-in sheet.
- Tests (`DropboxTests.swift`) run against `FakeDropbox` (in-memory HTTP server on 127.0.0.1 that checks PKCE, refresh tokens, content hashes and upload offsets, keeps every revision; `authorize(_:)` plays the browser) through `DropboxHosts`; they cover sign-in, reconnect, removed access, refresh, revoke, listing pages, every write path, the copy engine up and down (appended, truncated, rewritten sources both ways, plain and verify modes), server-side copy and move.

### Security notes

- FTPS checks certificates against the system trust and asks on untrusted or changed ones. FTPS explicit never falls back to plaintext.
- Credentials and archive passwords live only in the Keychain. **Never pass passwords on a subprocess argv** (`7zz`, `unrar`, `git`), because other processes can read argv. Use stdin, a pty or an API instead.
- SFTP must check known_hosts and prompt on unknown or changed host keys.
- LuaJIT on a hardened runtime needs the `com.apple.security.cs.allow-jit` entitlement.

### F3 / F4 / terminal (implemented for local files)

- F3 (`QuickLookController.swift`): Quick Look of the selected items, or the cursor item when nothing is selected. `PaneTableView` is the panel's responder-chain controller. The panel is key while open, and its key events go to the active pane's `keyDown` (Escape stays with the panel), so Up/Down move the cursor, Space selects and F3 closes. The preview follows the cursor; each newly previewed name is announced, because VoiceOver is in the panel.
- F4 (`MainWindowController.editCursorItem`): edits the cursor file. `BasilSettings.editorRules` (`EditorRule`, BasilCore `EditorRules.swift`) are pattern lists in quick-filter syntax (`*.txt;*.md`, exclusions after `|`) plus apps; the first matching rule with apps wins, one app opens directly, several show a menu at the cursor row; no match uses the global editor (`editorAppPath` or the system default, TextEdit for unclaimed files). Settings tab "Editor and Terminal".
- Cmd+Shift+T (`TerminalLauncher`, BasilIntegrations): `TerminalCatalog` lists terminals by bundle ID with a launch template: open the folder with the app (Terminal, iTerm2, Ghostty, Warp), run the bundle's executable with `{dir}` arguments (WezTerm, Kitty, Alacritty), or a custom shell command where `{dir}` is the single-quoted path. Plugins can `register` more. Default Terminal.
- Files inside archives (`TemporaryCopies.swift`, `ArchiveEditing.swift`): copies are made by the copy engine (plain mode) into `~/Library/Caches/Basil/Copies/<uuid>/name` (UI tests: the test data folder), which is emptied at launch and at quit. F3 hands Quick Look `QuickLookController.Item`s whose URL is filled in once the file is extracted (when the panel asks for that item), then refreshes; copies are reused until no pane shows the archive (`dropPreviews`, on each directory change). F4 extracts a fresh copy and watches it by size and modification date; on `didBecomeActive` each changed copy gets one sheet (Update / Not Now / Stop Watching); Update queues `ArchiveUpdateOperation(.update(source:entry:))`, which replaces the entry. Archives that can't be changed open the copy unwatched with a spoken note. `applicationShouldTerminate` asks before losing copies that were not put back.

- UI tests: Xcode sandboxes the test runner, so files it creates are unreadable by Basil. Debug builds launched with `BASIL_UITEST_FIXTURE=1` create the fixture themselves (`App/Sources/UITestFixture.swift`), start both panes in it, and use an isolated preferences domain (`com.erion.basil.uitests`, wiped each launch). Tests must never touch the user's real settings. Pass `UserDefaults` in explicitly; don't use `UserDefaults.standard` in BasilUI.
- The accessibility audit has three documented exceptions in the tests: SwiftUI Picker and Menu pop-ups ("Action is missing", a false positive), disabled controls, and list cells labelled with a file name that has an extension ("Label not human-readable" for "notes.md"; handled app-wide by the `audit(app)` helper in PaneUITests.swift, which every test uses instead of calling `performAccessibilityAudit` directly). Anything else fails the test. A text field that is being edited makes the audit report "Parent/Child mismatch" (the AppKit field editor), so tests move focus out of the field (Tab) before auditing.
- 200k-item benchmark (skipped unless `BASIL_PERF_DIR` is set): `BASIL_PERF_DIR=/path/to/big swift test -c release --package-path Packages/BasilUI --filter largeDirectory`. Last result: load and sort 0.87 s, re-sort 0.10 s, filter 0.04 s.
- Package unit tests use **Swift Testing** (`import Testing`). App-level UI tests use XCTest/XCUITest.
- `xcodebuild` prints `DVTCoreDeviceCore` / "CoreSimulator is out of date" plug-in errors on this machine. They are Xcode environment noise and do not affect macOS builds.
- Run `scripts/bootstrap.sh` once after cloning: it builds `Vendor/libssh2` (OpenSSL and libssh2 into an xcframework that SwiftPM needs when it resolves packages, about 20 s the first time) and 7zz. BLAKE3, libarchive and UnRAR need nothing: `Vendor/BLAKE3`, `Vendor/libarchive` and `Vendor/unrar` are SwiftPM packages of C/C++ sources, and `Vendor/7zip/build.sh` builds 7zz (about 4 s, then only what changed; the app's build phase runs it too) (`swift test --package-path Vendor/BLAKE3`). Their C targets print "no rule to process file ... module.modulemap" warnings, which are harmless. LuaJIT will be added to bootstrap.sh when M7 starts.
- The audit samples screen pixels, so elements of windows covered, dimmed (behind a sheet) or made inactive by the audited window fail "Contrast". Every audit of a sheet, the Settings window, Multi-Rename or the queue panel ignores contrast issues outside that window or scrolled partly out of it (`isCoveredElsewhere`, an `XCTestCase` extension in PaneUITests.swift); the main window is audited on its own. The suite passes in dark mode; light-mode contrast audits report false failures on macOS 27.2 (see progress.md).
- Secondary text: use `Theme.secondaryText` (AppKit) or `Theme.secondaryTextColor` (SwiftUI, the primary colour at 85 percent), not the system secondary colour (about 3.5:1 in light mode). In SwiftUI do not use `Color(nsColor:)` of a custom dynamic theme colour for text: the audit misreads it and fails it in dark mode.
- AppKit `NSTableView` cells: accessibility names a cell after its column identifier, so identifiers must be words, and each cell view gets `setAccessibilityLabel` with its text, or the audit fails ("Label not human-readable").
- Sheets open animated: UI tests wait for the field's `hasKeyboardFocus` before typing, or keys get lost.
- SwiftUI `Toggle` and `Stepper` inside a grouped `Form` expose no label on the switch/stepper itself (the text is a separate static text). Always add `.accessibilityLabel` with the same text.
